# 创始人说过的话（需求与纠正）

这份文档记录创始人对 Toward Us / 彼此 说过的每一条需求和纠正，归并成一条条要点。它是产品该怎么做的第一依据：和代码、旧文档冲突时，以这里为准；这里和创始人最新的话冲突时，以最新的话为准，并当场改这里。

**维护规则（所有 agent 都遵守）**
- 动手做 Toward Us 的任何任务之前先读一遍。
- 创始人每说一句新的需求或纠正，当天加进对应主题；和旧条目冲突就改旧条目，不并存两条。
- 每条写成"应该怎样"，后面括号注日期，能引原话就引一小句。
- 只记创始人的意思，不记实现细节；实现与状态写在 `docs/multi-principal-relationship-agent.zh-CN.md`。

---

## 1. Toward Us 是什么

- 属于两个人的关系 Agent：帮恋人和夫妻沟通、决定、计划、记事、守承诺；任何一方都不能单独控制共同 Agent。（9 月）
- 2026-11 重启，在旧版 toward-us 仓库上改，不换底子。（11-01）
- 产品不能就叫 Toward Us，要换一个有趣、和同类情侣产品明显不一样的名字。（11-01）
- 新名字定为 Pinky（拉钩的意思：两个人都同意才算数）；三种语言都叫 Pinky，"拉钩"只放在中文宣传语里。（11-01，"选 Pinky"）
- 核心场景：先是"难开口的话"——私下跟自己的 Agent 说，整理成对方听得进去的版本，本人确认后才交给对方；接着是"说到做到"——谈出来的约定双方批准同一版本，变成承诺、提醒和复盘。（11-01）

## 2. 入口与形态

- 先做成手机 App，和人脉/Onegent 一样的做法；"网页版的大家不怎么会用"。（11-01）
- 也要像 iMessage 助手那样，直接发条消息就能对话、办事；App 和 iMessage 两种入口都要。（11-01）
- iMessage 里：你和 Agent 私聊 = 私人 Agent（只有我）；你、伴侣和 Agent 三人群 = 共同 Agent（我们俩）。（11-01）
- App 默认画面是对话，像现在所有通用 Agent 一样；以对话为主，其他为辅。（11-01）
- 对话和原来的完整界面要融合成一个产品，不分两条轨道：不能有两个对话框（首页一个、对话一个）互相冲突，也不要像传统 App 那样一堆功能页；要 AI native。（11-02，"不要分轨道……我要把它们融合在一起"）
- 不需要看的功能没有入口，直接在对话里说就办完，比如"帮我记着一件事"；需要看东西、需要界面的才有入口，比如看回忆。（11-02）
- 第一版 App 和 iMessage 一起上。（11-01）
- 对话首页左上角不放语言切换；语言切换放到设置里。（11-01，"不应该放在左上角"）
- 对话首页左上角是左侧抽屉（像 ChatGPT/Claude）：上面是"我们俩的"（约定、日程、回忆、清单、调解与决定），下面是"只有我的"和设置；对话永远占满全屏，抽屉只用来翻看，做事回对话里说。不用底部标签栏。（11-02，选"A 左侧抽屉"；"左上角才是大家的习惯"）
- 只维护手机版，永远不再维护电脑版：设计、修改和验收都只看手机，电脑网页不再投入。（11-02，"永远都只维护手机版"；11-01，"主要就是做手机，不做电脑"）

## 3. 功能取舍

- App 里旧版功能全部保留：还不知道用户喜欢哪种，让用户自由选择，想调解就调解，想做别的就做别的。（11-01，"那功能我们都必须得有"）
- 约定走轻量路径：在"我们俩"里谈 → Agent 起草 → 双方批准同一版本；旧版完整共同决定流程留在完整界面，作为认真商量大事的选项。（11-01）
- Agent 在群里只在被叫到、有正事（待批准约定、提醒、复盘）或转达已确认分享的话时开口；两人聊天、吵架时不插话、不评论。（11-01）

- 四件事都是核心，第一批情侣都要能反复用：难开口的话、说到做到（约定）、吵架时调解、日常记事与回忆。（11-02，"四个全部都要"）
- 调解房间不再单独存在，并进"我们俩"对话的语音模式；面对面一台手机和各用各的手机两种都要。（11-02）
- 要有和 Pinky 实时通话的按钮（像人脉那样）：接通后不管在场几个人，Pinky 都能听到并用语音回应；调解时需要有第三个人在旁边听。用 OpenAI 实时语音；"我们俩"和"只有我"两边都有；多人时 Pinky 靠听和问来分清是谁说的，不用点屏幕。（11-02）
- 正式共同决定并进对话：Pinky 在各自"只有我"里私下问观点，在"我们俩"里发分析和约定草稿，到期在"我们俩"提醒复盘；不再有单独的决定页面。（11-02）
- 在"只有我"里，Pinky 只在用户设好的提醒时主动开口。（11-02）
- 回忆要能放照片。（11-02，"要照片"）
- 不要 hard code：每对情侣想用的地方都不一样（有的爱存美好回忆，有的要调解，有的要别的），不能写死很多功能页和流程；要给很大自由度，让模型去完成任何一对情侣想解决的问题、想做的事。只有隐私、确认、双批准这些保证写死。（11-02，"不能就是说写了很多 hard code 的代码……让我们的模型完成它"；在人脉上和 Codex 犯过这个错）
- 参考 Maia、Twoo 这类产品的长处，我们自己的创新点也都要有。（11-02）
- 抽屉：只固定少量（约定、即将到来），其余空间由 Pinky 按每对情侣的需要建。（11-02，选"少量固定 + Pinky 建的空间"）
- 第一版就要能替用户对外办事（订餐厅、买东西、给别人发消息等）。（11-02）
- 要能导入两人过去的聊天记录（微信、WhatsApp、iMessage、Messenger 等），让 Pinky 分析两人之间的问题，也顺带整理回忆和日期；入口放在对话里，交给 Pinky。（11-02）
- 导入不能让用户自己摸索去别的平台导出：能自动的就在用户提出后自动完成；做不到自动的，要给第一步、第二步……的详细指导；导入后要自动检测到并自动开始分析。（11-02，"让他们手动去……导出聊天，会很麻烦"）

## 3.5 渠道与开销

- Toward Us 单开一个 Sendblue 号码，用付费线路和 webhook，不和人脉共用；群聊开不通也照样上，先只做私聊。（11-01）
- Apple 开发者账号用公司 Witnora, Inc. 名义，继续等 D-U-N-S 编号，不先用个人身份开。（11-01，"继续等公司编号"）
- 等编号期间先把产品做好、功能做完，不花钱开账号、不恢复线上；先自己在本地内测使用。（11-01，"我们先做产品，自己内测，本地用就可以"）
- 内测阶段 AI 先用 Claude 订阅额度（本机 claude 命令），不用 OpenAI API；后期再转 API，效果要和 API 差不多。（11-02，"先用我们 Claude 的订阅额度……后期再转用 API"）
- Render 暂时不升级（11-01，"这个 render 先暂时不要升级"）；Sendblue 套餐、Apple/Google 开发者账号一并批准，动手前先查价格报给创始人。（11-01）

## 4. 隐私

- 旧版隐私规则原样沿用：私人内容只有本人能看；每次分享都要本人先看到将发给对方的那一版并确认；约定双方批准同一版本。（11-01）
- 导入的聊天记录先做"只属于导入者"（对方看不到，只有本人确认的摘要能进"我们俩"），之后再做"双方同意后共享进我们俩"；两种都要。（11-02，"先做 A，然后做 B，两个都其实都有用"）

## 5. 用户与成功标准

- 第一批用户：身边 5–10 对情侣，用内测包；跑通后再公开上架美区/海外。（11-01）
- 成功以留存为主：第 4 周还有几对是两个人都每周在用。（11-01）

## 6. 做事方式

- 动手前先认真问、把设计想清楚；给选项时列利弊和推荐。（11-01）
- 产品细节照主流成熟产品的惯例做；打开就不累。（11-01）
- 不写测试，只认真机验证。（11-01）
- 自己看、自己修：改完要自己在手机上把相关界面（中英西三种语言）逐个看一遍，发现问题自己改，不要等创始人打开、发现不对再来告诉。（11-01，"你得自己学会来看，然后来自己纠正"）
- 每次的建议和修改需求都记进这份文档。（11-01）
- 做完一轮不要等创始人说下一步：自己推进、自己找问题、自己完善，直到产品成熟到第二天验收就能直接开始用。（11-02，"你自己把它这个产品继续完善……很成熟、很完美"）
- 好用程度对标当下最火的通用 Agent（Claude、GPT、Grok、Meta 等的通用助手）；缺什么工具就搞什么工具；要像 Claude 那样能连很多外部服务。（11-02）

## 7. 旧版已记录的界面要求（原在 AGENTS.md）

- 整体红蓝对比风格保留；不好看的是细节：文字、输入框、按钮这些要做精致。（11-01，"整体还可以……主要是字和输入框还有那些东西细节不好看"）
- 设置页要像成熟 App 的设置那样专业好看（分组列表、一行一项、点进去看细节），不能是一大段说明文字。（11-02，"这个设置界面有点丑呀……看起来非常简陋"）

- 调解房间以 AI 为主，一整块米白底：上面是转写，下面是 AI，不加卡片边框或硬分隔。（9 月）
- 界面完整支持简体中文、English、Español，选择器写 `ZH / EN / ES`；非中文模式不显示"彼此"或任何中文界面文字。（9 月）
- 共享空间导航和首页入口说明要舒服易读，不用小号低对比文字。（9 月）
- 日常事务语音优先，同时保留所有原有能力和文字/触控路径。（9 月）
