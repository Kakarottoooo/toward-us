# Pinky 重启设计摘要（定稿，待创始人最终确认）

日期：2026-11-01 · 底子：`Kakarottoooo/toward-us` main（`cf5c042`）· 创始人原话记录：`docs/founder-voice.md`（PR #7）

## 一句话

属于两个人的关系 Agent：发一条 iMessage 或打开 App 就能说话。它先帮你把难开口的话说好，再帮你们把说好的事做到。

## 为什么重启

旧版功能很全，但它是网页，"大家不怎么会用"，每件事都要走很多步。重启要解决两件事：随处都能说话、打开就不累。

## 核心闭环（第一版必须跑通）

两人配对 → 一方在"只有我"里说难开口的话 → Agent 整理出给对方的版本，本人确认 → 发到"我们俩" → 两人在里面谈出约定 → 双方各自批准同一版本 → 变成承诺，到时提醒 → 到期后两人各自私下复盘，双方都完成才形成共同结果。

## 目标、非目标、反目标

- **目标**：上面的闭环在 iMessage 和 App 两边都能完成，并且两边结果一致；旧版全部功能在完整界面里可用。
- **非目标（第一版不做）**：公开上架；中国大陆上架；微信和 Telegram 入口；把每个旧功能都接到对话里（没接上的从完整界面进）；旧版关着的日历、位置、财务、亲密匹配继续关着。
- **反目标（做出来也算失败）**：
  - Agent 在群里引用或暗示某一方的私聊内容；
  - Agent 当裁判、判谁对；
  - 关系打分或监控对方；
  - 一方能单方面让约定生效；
  - 用户得学很多步才会用。

## 约束与已查实的事实

- **Sendblue 群聊**：接口仍在 beta，只在部分付费套餐开放；群里所有人都要开着 iMessage；不能把人移出群；用 `group_id` 对应到哪一对情侣。
  来源：https://docs.sendblue.com/getting-started/groups/
- **Onegent 现成的 Sendblue 私聊**：Python 写的（`social_agent/sendblue.py`，约 450 行）。免费线路靠轮询收消息，会丢弃所有群消息；SMS 不认身份，只有 iMessage 能接到 Agent。Pinky 是 Node，需要照着移植，再新做群聊。
- **安卓伴侣**：进不了 iMessage 群，在 App 的"我们俩"频道参与；这个频道和 iMessage 群双向同步。
- **数据经手方**：私聊内容会经过 Apple、Sendblue 和模型提供方，隐私政策和内测告知里要写清楚。
- **旧版现状**：Node/Express，PostgreSQL 或本地 JSON，OpenAI，部署在 Render 免费层（会休眠，提醒可能延迟）；手机推送只有网页推送，没有原生推送。

## 我替创始人做的判断（请核对）

1. **实现原则**：闭环和全部规则只在服务端实现一次；iMessage、App 对话、完整界面都只是很薄的入口。
2. **完整界面**：沿用旧版页面，只整理入口，不重画。
3. **对话第一批能办的事**：旧版语音办事已经覆盖的提醒、记录、计划和查询，再加上 C 和 D。
4. **身份**：陌生手机号第一次发消息时，回一个一次性链接，用旧版账号登录或注册后绑定这个手机号（照 Onegent 的做法）。
5. **建群**：两人配对完成、都绑好手机号后，由 Agent 发起三人群并发一句开场白。
6. **群里的双批准**：Agent 在群里贴出约定全文和版本号，双方各自回复同意，Agent 按发信手机号认人；App 里同一张卡上有批准按钮。同一时间只有一个待批准的约定，避免回复对不上。
7. **成功门槛**：10 对里，第 4 周至少 4 对两个人都还在每周用；辅助看闭环完成数和各功能的使用分布。这两个数字是我拍的。功能使用只记"做了什么动作"，不记内容。
8. **一个用 iPhone、一个用安卓的情侣**：不建 iMessage 群，两人都用 App 的"我们俩"；用 iPhone 的一方仍可以在 iMessage 私聊里用私人 Agent。配对不要求先装 App，点链接用网页兜底也能完成。
9. **三语**：中文和英文为主做验收，西语保留但不作为重点。
10. **验证**：旧版已有的自动测试照常跑，新功能不新写测试，以真机验收为准。
