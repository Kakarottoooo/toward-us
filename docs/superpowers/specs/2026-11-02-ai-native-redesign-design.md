# Pinky AI native 重设计

日期：2026-11-02。依据：创始人当晚的决定（已记进 `docs/founder-voice.md`）。只做手机版。

## 为什么改

现在的 App 是两个产品叠在一起：对话首页一个输入框，"全部功能"里的共同空间首页又一个，私人空间、计划页、决定页里还各有 Agent 输入框和语音助手；沟通、决定、计划、回忆是一排写死的传统功能页。用户不知道该在哪儿说话；而且每对情侣想用的地方都不一样（有的爱一起存美好回忆，有的要调解，有的要别的），写死的页面和流程装不下。

## 一句话

**只有两个对话——"只有我"和"我们俩"。Pinky 有一组通用能力，由模型按这对情侣的需要组合着用；左侧抽屉只用来翻看结果。流程交给模型，保证交给代码。**

## 设计原则

1. **流程不写死。** 调解、做决定、计划旅行、感恩日记、装修清单……都是模型用通用能力临场组合出来的做法，不是写死的页面或步骤。新的需求优先靠给模型新能力或改提示解决，不加专用页面。
2. **保证写死。** 只有模型不能判断的规则才由服务端写死并强制执行（见"不能破坏的规则"）。这是我们和 Maia、Twoo 不同的地方：两个人各有一个私人 Agent、共享一个共同 Agent，私人内容永远只属于本人，进入共同空间必须本人确认，约定必须两人批准同一版本。
3. **个性化来自记忆，不来自分支代码。** Pinky 从对话里慢慢记住这对情侣是谁、在意什么、常用什么（Twoo 的"记住 → 理解 → 行动"），据此决定建议和建什么空间。私人 Agent 记得的东西只给本人看、本人能改；共同 Agent 记得的东西两人都能看、都能改。
4. **界面是少量通用的展示方式，不是一个功能一个页面。** 空间用几种通用展示（列表/清单、时间线、相册、笔记），由 Pinky 建空间时选。
5. **对话里办完就够的，不需要入口。**

## 参考

- Maia：私人文字和语音对话、AI 语音帮两人当场处理分歧并给反馈和行动项、每日活动、测验、主动洞察。
- Twoo：AI 夹在两个人之间当组织者；共同记忆是核心；用户自己把它扩展到家人、朋友、搭子。
- 我们要有的：上面这些能力（实时调解、主动但克制、共同记忆、游戏化可以以后加），加上我们独有的双人主体、私密到共享的确认、双批准约定和"说到做到"的提醒与复盘，以及 iMessage 入口。

## 目标

- 第一批 5–10 对情侣，下面四件事都能反复用，四件都是核心：难开口的话、说到做到（约定）、吵架时调解、日常记事与回忆。除此之外，任何一对情侣想做的事都应该能通过和 Pinky 说话做成。
- 第一版就能替他们对外办事（见第 6 步）。

## 不做

- 不加底部标签栏，不保留"共同空间首页"，不做电脑版。
- 页面里不再出现第二个对话框或语音助手。
- 不写死每日打卡、写死的决定步骤、写死的调解步骤。
- Pinky 在"只有我"里只在用户设好的提醒时主动开口；在"我们俩"里只在被叫到或有正事（待批准约定、提醒、复盘、转达已确认的话）时开口。

## 不能破坏的规则（服务端写死）

- 私人内容只有本人能看，按人投影，不靠前端隐藏。
- 任何内容从"只有我"进入"我们俩"或共同空间，都要本人先看到将要发出的那一版并确认。
- 约定、以及任何同时约束两人的对外动作（例如花共同的钱、替两人订东西），要两人批准同一版本。
- 只代表一个人的对外动作（例如替我给某人发消息），本人确认那一版后才执行。
- 每个长期对象保留来源、可见范围、AI 可用范围和批准规则。
- 三种界面语言完整。

## Pinky 的通用能力（模型可以自由组合）

| 能力 | 说明 |
|---|---|
| 回复 | 在当前对话里说话 |
| 私下问 | 在某个成员的"只有我"里问他、等他答（例如做决定时分别问两人的想法） |
| 在"我们俩"里发言 | 遵守"什么时候开口"的规则 |
| 整理后请本人确认再分享 | 难开口的话、私下观点的可分享版本 |
| 起草约定 | 两人批准同一版本后生效，可带后续提醒和到期复盘 |
| 提醒与回头看 | 在某个时间提醒某人，或约好时间回来跟进 |
| 记住 | 存一条回忆或事实（可带照片），标明私人还是共同 |
| 建空间、往空间里放东西 | 选展示方式；私人空间或共同空间 |
| 听与分析 | "我们俩"语音模式下听两个人说，结束后分别私下反馈、共同分析 |
| 对外办事 | 查信息、准备好要办的事、确认后去办（见第 6 步） |

## 抽屉

左上角按钮拉出，盖在对话上，点外面或往左滑关闭；打开前先收起键盘、停掉语音。

- 顶部：PINKY 和自己的名字。
- **固定两项**：约定（待批准 / 进行中 / 历史）、即将到来（所有带时间的事：提醒、纪念日、到期复盘）。
- **我们俩的空间**：Pinky 为这对情侣建的共同空间，一开始可能一个都没有；已有的回忆、清单、纪念日数据作为现成空间出现（有内容才出现）。
- **只有我的空间**：本人的私人空间、Pinky 记得的关于我的事。
- 还没配对时：顶部多一项"邀请 TA 一起来"，共同空间这一组不显示。
- 底部：设置（隐私、账号、语言）、退出登录。

页面顶上只有"← 返回对话"和标题。页面只看和做小改动（勾选、删除、改时间）；底部"跟 Pinky 说"带着一句开头回到对话。

## 现有功能怎么处理

| 现有 | 处理 |
|---|---|
| 只有我 / 我们俩对话、难开口的话、轻量约定 | 留，是骨架 |
| 计划、纪念日、提醒、心情、回忆、清单 | 在对话里说；数据保留，作为现成空间或"即将到来"出现 |
| 正式共同决定 | 不再是写死的页面和步骤；Pinky 用"私下问 + 分析 + 起草约定 + 回头看"自己完成。复用现有议题、观点、分析、承诺、复盘对象 |
| 调解房间 | 并进"我们俩"的语音模式，面对面一台手机和各用各的手机两种都要 |
| 共同空间首页、私人空间页、通知中心页、页面里的语音助手和 Agent 输入框 | 删。通知改为对话里的消息加系统推送 |
| 隐私与账号、语言 | 抽屉底部"设置" |
| iMessage | 留，规则同 App |

## 分步做（每步单独提交，做完自查再做下一步）

1. **外壳**：做抽屉（固定两项 + 现成空间 + 设置）；删掉共同空间首页、导航栏、私人空间页、各页面的语音助手和多余输入框、"回到对话"浮动按钮；页面头部换成"返回对话 + 标题"。
2. **通用空间**：服务端新增"空间"和"空间条目"（带可见范围、来源、版本），几种通用展示；私人 Agent 和共同 Agent 能建空间、加改条目；从私人进入共同照常要本人确认。旧的回忆、清单、纪念日以现成空间显示。
3. **通用能力进 Agent**：给两个 Agent 加"私下问""回头看""记住关于这对情侣的事"等能力；正式决定改由模型组合完成；抽屉里能看、能改"Pinky 记得的事"。
4. **"我们俩"语音模式**：面对面（每段开口前选是谁）和各用各的手机两种；结束后分别私下反馈和共同分析，需要时起草约定。复用现有调解分析。
5. **照片**：对话里能发照片；Pinky 存进回忆或空间（相册展示）。"只有我"里的照片默认私人，分享照常确认；本地内测时存在数据文件旁边的文件夹，通过登录后的接口按人取。
6. **对外办事**：先做不花钱的部分：上网查（餐厅、地点、活动）、把要办的事准备好（预填好的预订或叫车链接、日历邀请、要发给别人的消息）、确认后交给手机去完成。真正由 Pinky 自己去订、去付钱、去发消息需要接付费服务和第三方账号，先查清价格和选项报给创始人批准，再接入。

## 留给实现时自己定的（我的判断）

- 抽屉和空间的具体样式沿用现有红蓝与控件；时间线按月分组。
- 删除的旧页面代码直接删，不留开关。
- 空间的展示方式先只做列表/清单、时间线、相册、笔记四种。

## 还没定、不影响今晚开工的

- 正式上线时照片存哪里（对象存储，要花钱，到时报价）。
- 对外办事接哪些付费服务（订餐、购物、代发消息），到时报价。
- iMessage 里发的照片是否存进回忆。

## 验收

每步做完：在手机尺寸下用无头浏览器把相关画面中英西三种语言逐个看一遍，发现问题自己改；跑现有测试保证没坏。创始人早上解锁手机后，在 iPhone 上做真机验收。
