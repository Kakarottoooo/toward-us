# Pinky 交接 ·「我们有多合拍」陪伴主题

## 给接手人的第一句话

继续维护仓库 `Kakarottoooo/toward-us` 里已有的 Pinky 手机界面。打开左上菜单 →「我们有多合拍」→「我的发现」。这次完成的是一个完整主题「心情不好时，希望 TA 怎么陪我？」。基于用户已有的合拍页进行修改。这个主题独立于每日双人题卡、小游戏、聊天模型评测以及 iOS 外壳。

## 创始人为什么要求重做

上一版让人先做六道题，每个方面一道。结果页有六个大标题，正文基本是「你选了……」。一次奖金用途的选择支撑不了「金钱、家庭与未来」，同样的倾诉偏好也不代表两个人相处得好。创始人希望用户少量进入、逐步深入，能读到值得认领的发现，知道理由，还能说给伴侣听。创始人反复指出，选项只要暗示哪个人更体贴，很多用户就会给出理想伴侣的答案。题目应给出同样说得过去的选择，允许跳过和记不清。

## 手机上的实际流程

1. 个人先做四个场景。依次是刚想开口时希望怎样开始、上一次对方安静时自己做了什么、当天还有难回的消息时需要什么、上一次别人找自己倾诉时做了什么。前三题从不同处境了解接收陪伴，最后一题单独记录给出陪伴的经历。四题都已作答或跳过，且前三题至少有两题选了具体答案，才有可确认的发现。这个门槛只是本主题的出文条件，没有心理测量含义。
2. 个人首屏读一条发现，按需展开题目与本人答案。用户可以选「像我」「有时候是这样」或「我想改一句」，也可以暂时只留给自己。作答不足时显示线索或继续入口。其他六个主题的 18 道题、自己的历史答案、已有 MBTI 和星座入口继续可用，旧答题记录不换算成新发现。
3. 确认自己的说法后，先预览分享。预览写明自己愿意收到怎样的陪伴；第四题若有作答，再列出自己上一次怎样陪别人。两人都对当前关系、同一主题和各自当前版本授权后，页面才展示两个方向：「我心情不好时」和「TA 心情不好时」。每个方向分别使用倾诉者确认的说法和另一人自己报告的做法。自写文案或条件性回答保留原意，跳过的陪伴经历保持未知。
4. 分享确认会在「我们俩」发一条邀请。另一个动作「带回我们俩聊聊」只把建议放进双人聊天草稿，由用户决定如何编辑、是否发出。两者的发送行为不同，交接时应讲清。
5. 改答会让此前共享版本失效；修改新主题的原始作答还会清除此前对发现的确认。可撤回、删除或重新分享。原有双方仍在用旧主题时，保留之前对旧内容的授权及原有展示范围。新旧授权不混用。

**一个实际文案例子。** 如果用户选了事情已经过去后希望从头讲、还得赶着回消息时希望两人一起想办法，发现的开头是「事情已经过去时，我想先讲完；如果还等着我拿主意，我反而想和你一起找个开头。」用户能找回这两道题的原答案，也可以把这句话改成自己平时会说的话。这是根据选项生成的草稿。

## 实现位置

| 文件 | 拥有什么 |
| --- | --- |
| `server/fit-support.mjs` | 四道新题、稳定选项 ID、中英西文案、个人发现、分享投影以及两个方向的解析。这里使用确定性规则，未接入额外模型调用。 |
| `server/fit-questions.mjs`、`server/fit-report.mjs` | 新主题注册、旧题保留、个人和旧双人报告。旧六题的 ID 与新题分开。 |
| `server/fit-router.mjs` | 通过现有私人档案保存答案和确认。复用版本、事务、关系成员和撤回机制；`POST /api/fit/support-review` 用于确认或改写，`POST /api/fit/sharing` 用于明确授权。旧客户端不能用旧的分享请求授予新主题的权限。 |
| `src/features/fit/FitPage.tsx`、`types.ts`、`fit.css`（同目录） | 答题/恢复进度、证据折叠、确认和编辑、版本化分享预览及双人报告。 |
| `src/features/conversation/ConversationHome.tsx` | 已有左侧入口与双人聊天草稿回调。 |
| `docs/founder-voice.md`、`docs/features.zh-CN.md` | 创始人决策与功能清单。 |

沿用同一个问题 ID 时应保留选项的原意。若以后改变问题含义，新增 ID 并保留旧答含义。共享内容仅限预览中的可分享信息；个人的依据和旧记录不应被夹带到新双人报告。
